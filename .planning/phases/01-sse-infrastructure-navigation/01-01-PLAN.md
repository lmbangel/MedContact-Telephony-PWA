<task type="auto">
  <name>Task 2: Create SSE endpoint with heartbeat and cleanup</name>
  <files>api/handlers/stats_sse.go</files>
  <action>
Create a new file `api/handlers/stats_sse.go` that implements SSE streaming.

DO NOT use alexandrevicenzi/go-sse library - implement hand-rolled SSE for better control. The research recommended the library, but for this simple use case (single channel, heartbeat only in Phase 1), hand-rolled is simpler and avoids external dependency.

The handler must:
1. Set SSE headers: Content-Type: text/event-stream, Cache-Control: no-cache, Connection: keep-alive
2. Check for http.Flusher interface (required for SSE)
3. Create a ticker for 30-second heartbeat pings
4. Use a for-select loop:
   - case <-r.Context().Done(): cleanup and return (CRITICAL: detects client disconnect)
   - case <-ticker.C: send heartbeat ping
5. CRITICAL: Use `defer ticker.Stop()` to prevent goroutine leaks
6. Send SSE message format: "data: {json}\n\n"

Heartbeat message format:
```json
{"type": "heartbeat", "timestamp": "2024-01-15T10:30:00Z"}
```

Create an SSEServer struct that holds the handler and can be extended later:
```go
type SSEServer struct {
    queries *db.Queries
}

func NewSSEServer(queries *db.Queries) *SSEServer
func (s *SSEServer) HandleStatsStream(w http.ResponseWriter, r *http.Request)
```

Log when clients connect and disconnect for debugging.
  </action>
  <verify>
Run `go build ./...` from api directory - should compile without errors.
Verify file exists with SSEServer struct and HandleStatsStream method.
  </verify>
  <done>
SSE handler exists that sends heartbeat pings every 30 seconds, properly detects client disconnect via context.Done(), and cleans up ticker on exit.
  </done>
