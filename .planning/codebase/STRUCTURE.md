## Directory Purposes

**api/:**
- Contains complete Go backend server
- Database schema and migrations
- All HTTP handlers and business logic
- Dockerfile for containerization
- Runs on port 8000 by default

**app/src/:**
- All frontend application code
- Modular service-based architecture
- Vite as build tool and dev server (port 5173)

**app/src/js/services/:**
- Singleton service instances exported for import
- Each service handles specific domain (auth, calls, customers, tasks, Twilio)
- No UI code, only data fetching and business logic

**app/src/js/ui/:**
- Minimal UI layer, currently only ScreenController
- Handles DOM manipulation and screen transitions
- Subscribes to CallStore for state updates

**migrations/:**
- Database migration files (generated by sqlc or manual)
- Located: `/api/migrations/`

## Key File Locations

**Entry Points:**

**Backend:**
- `api/main.go`: Initialize server, setup router, start listening
- Route definitions: lines 254-304 in `api/main.go`

**Frontend:**
- `app/phone.html`: Softphone SPA, loads main.js
- `app/index.html`: Auth router, loads login.js or register.js
- `app/src/main.js`: Softphone initialization, call state management

**Configuration:**

- `api/.env`: Database credentials (DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD), CORS origins
- `app/src/config.js`: API_URL, API_ENDPOINTS mapping
- `app/vite.config.js`: Build configuration
- `app/tailwind.config.js`: CSS configuration
- `api/sqlc.yaml`: SQL code generator configuration

**Core Logic:**

- Authentication: `api/main.go` functions `register()`, `login()`, `getCurrentUser()`
- Twilio integration: `api/main.go` function `getTwilioToken()`, `app/src/js/services/TwilioService.js`
- Call handling: `app/src/main.js` (orchestration), `app/src/js/services/TwilioService.js` (Twilio SDK)
- Customer lookup: `app/src/js/services/CustomerService.js`, `api/main.go` function `getCustomerByPhone()`
- State management: `app/src/js/services/CallStore.js` (observable pattern)

**Testing:**

- Not detected - no test files found

**Database Schema:**
- `api/schema.sql`: Complete MySQL schema (users, sessions, customers, calls, tasks, agent_status, etc.)
- `api/queries.sql`: Raw SQL for all database operations (input to sqlc)

## Naming Conventions

**Files:**

- Backend: Snake_case for Go files (`main.go`, `db.go`, `queries.sql.go`)
- Frontend: PascalCase for service/class files (`AuthService.js`, `TwilioService.js`, `CallStore.js`, `ScreenController.js`)
- Frontend: Kebab-case for feature files (`dashboard-home.js`, `dashboard-login.js`)
- HTML: Kebab-case (`phone.html`, `index.html`)

**Functions:**

- Backend (Go): camelCase (e.g., `register()`, `getTwilioToken()`, `getCustomerByPhone()`)
- Frontend (JS): camelCase for functions (e.g., `formatPhoneNumberDisplay()`, `normalizePhoneNumber()`)

**Variables:**

- Backend (Go): camelCase (e.g., `dbHost`, `sessionID`, `hashedPassword`)
- Frontend (JS): camelCase (e.g., `currentUser`, `currentConnection`, `activeScreen`)

**Types:**

- Backend (Go): PascalCase structs (e.g., `RegisterRequest`, `AuthResponse`, `TaskStatsResponse`, `Server`)
- Frontend (JS): PascalCase for classes (e.g., `AuthService`, `TwilioService`)

**Constants:**

- Backend (Go): PascalCase (e.g., `DefaultCost` from bcrypt)
- Frontend (JS): UPPER_CASE for true constants (e.g., `API_URL`, `API_ENDPOINTS`)

**Database:**

- Tables: Snake_case (e.g., `users`, `customers`, `agent_status`, `otp_codes`)
- Columns: Snake_case (e.g., `password_hash`, `medical_aid_provider`, `created_at`)

## Where to Add New Code

**New Backend Feature:**
- Primary code: `api/main.go` (add handler function)
- Database access: Add query to `api/queries.sql`, regenerate `api/db/queries.sql.go` with sqlc
- Route registration: Add `r.Post("/api/endpoint", server.handlerName)` in main()
- Request/Response types: Add struct definitions at top of `api/main.go`

**New Frontend Page:**
- Create new HTML file in `app/` root (e.g., `settings.html`)
- Create corresponding script file in `app/src/` matching filename (e.g., `settings.js`)
- Reference entry point in HTML: `<script type="module" src="./src/settings.js"></script>`
- Import services as needed: `import { authService } from './js/services/AuthService.js';`

**New Frontend Service:**
- Create file: `app/src/js/services/FeatureService.js`
- Follow pattern: Export singleton instance at bottom: `export const featureService = new FeatureService();`
- Methods make fetch calls to `API_ENDPOINTS.*` or direct API_URL + path
- Use credentials: 'include' for authenticated requests

**New Component/UI Module:**
- Create file: `app/src/js/ui/ComponentName.js`
- Export class: `export class ComponentName { ... }`
- Handle DOM manipulation and event listeners
- Subscribe to CallStore if needs state updates: `callStore.subscribe(newState => { ... })`

**Utilities:**
- Shared helpers: `app/src/js/utils/` (directory doesn't exist yet, create if needed)
- Format functions: Add to relevant service or create `format.js`
- Validation: Add to service or create `validation.js`

## Special Directories

**api/migrations/:**
- Purpose: Version control for database schema changes
- Generated: Some files auto-generated by migration tools
- Committed: Yes, all migration files should be committed
- How to use: Run migrations with `sqlc` or manual SQL execution

**api/bin/:**
- Purpose: Compiled Go binaries
- Generated: Yes, from `go build`
- Committed: No, add to .gitignore
- Contains: `omnicall-server` executable

**app/node_modules/:**
- Purpose: npm dependencies
- Generated: Yes, from `npm install`
- Committed: No
- Contains: Vite, Tailwind, and plugins

**api/docs/:**
- Purpose: API documentation
- Generated: Potentially (if Swagger/OpenAPI used)
- Committed: Yes

**data/:**
- Purpose: Database backups, seed data, fixtures
- Generated: Some files during runtime
- Committed: Selectively (backups no, schemas yes)
